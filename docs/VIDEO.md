# Demo video shot list

Target: under 3 minutes. Everything below is real and reproducible from the repo.

## 0:00 to 0:25 — The thesis

Show `docs/architecture.md` diagram. Read the claim verbatim:

> You cannot achieve exactly-once against a non-idempotent external API by retrying. Retry gets you at-least-once. You get exactly-once by pairing a durable intent log with an external verifier, and that intent log has to commit in the same transaction as the memory write, or the agent's history diverges from reality.

Land the framing: "Everyone else is building memory stores. Correct memory writes
are solved. This is about an agent that acts."

## 0:25 to 0:55 — Incident, recall, action

Terminal, split with the panel at `http://localhost:8080`.

1. Fire an incident. Agent vector-searches memory, surfaces two similar past
   incidents with their similarity and salience scores.
2. Show the intent row appearing as `PENDING` in the panel **before** anything
   external happens. Say that out loud: the record is written first.
3. Agent executes through ccloud. Panel flips the intent to `COMMITTED` with an
   external reference and an evidence column.

## 0:55 to 1:55 — The core

**This is the segment that wins or loses the submission. Do not rush it.**

```sh
go test ./internal/protocol/ -run TestChaos_CrashBetweenExecuteAndCommit -v
```

Narrate what the test does: a **real OS process** performs the external action
and is killed with `os.Exit(9)` before it can record anything.

Show on screen, in SQL:
- the external world has 1 operation
- `action_intents` shows `PENDING` with an empty `external_ref`
- the episode is still `open`

Say it plainly: **the world changed and the agent's memory does not know.**

Then the reconciler runs. Show the log line:

```
audit log entry 382f4243-... records AUDIT_LOG_ACTION_CREATE_SQL_USER
for user "anchor_422b6af752e68501" ... via AUDIT_LOG_SOURCE_CLI
```

Point at the username: it is derived from the idempotency key, which is why this
is proof that *this* intent ran rather than a guess about world state.

Intent becomes `COMMITTED`, memory matches reality, and the world still shows
**exactly one operation**.

Now the control:

```sh
go test ./internal/control/ -run TestControl_DoubleActsOnCrash -v
```

Same incident, same API, same crash point. Show the output:

```
CONTROL DOUBLE-ACTED: the external world was scaled 2 times for one incident
```

Then the quieter failure, which is the direct answer to "why not Postgres plus
Pinecone":

```sh
go test ./internal/control/ -run TestControl_MemoryDivergesFromReality -v
```

No crash at all. The world changed, the relational store committed, the vector
store write failed, and nothing can roll back.

## 1:55 to 2:25 — Memory compounds

Third incident of the same class. Show the consolidated playbook in the panel:
its confidence, its `derived_from` provenance pointing at the source episodes,
and steps derived from intents that actually committed rather than from model
output.

Mention pinning: episodes with committed actions show `pinned`, so TTL can never
reap the audit trail.

## 2:25 to 2:50 — Numbers and contention

`docs/RESULTS.md`, generated by `cmd/bench`:

- 16 concurrent agents on one logical action: 1 committed, 15 deduplicated,
  **0 lost updates**, on both local and CockroachDB Cloud
- write and recall latencies for both environments

Then the contention view in the panel.

Close on the compliance table in the README: three CockroachDB tools, three AWS
services, each pointing at the file that satisfies it.
