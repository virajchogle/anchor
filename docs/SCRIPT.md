# Video script

Under 3 minutes. Everything here has been run end to end. Words in **bold** are
what you say; everything else is what you do.

**Setup before you hit record**

- Browser on the **Live run** page, terminal beside it, both large font
- `go run ./cmd/demo -reset` so the dashboard is empty
- Have these ready to paste, in order

Speak at a normal pace. The two places to slow down are marked.

---

## 0:00 — 0:22 · The claim

*Screen: the README, scrolled to the Mermaid diagram.*

> **Every agent framework right now treats memory as storage. Write it down,
> search it later. That's a solved problem.**
>
> **But the moment an agent actually does something to the world, correct memory
> isn't enough. Its record of what it did has to match what actually happened.**
>
> **You cannot get exactly-once against a non-idempotent API by retrying. Retry
> gets you at-least-once. You get exactly-once by pairing a durable intent log
> with an external verifier, and that intent log has to commit in the same
> transaction as the memory write, or the agent's history diverges from
> reality.**

*Point at the dotted line on the diagram.*

> **That dotted line is the whole project.**

## 0:52 — 1:50 · The core

**Slow down here. This is the segment that matters.**

```sh
go run ./cmd/demo -crash
```

> **The agent just created a real SQL user on the cluster, then died before it
> could record that it did.**

*Stop talking. Let the dashboard turn red. It takes about five seconds.*

> **The world has changed. The agent's memory has no idea. Any system that
> restarts here and retries will do it twice.**

```sh
go run ./cmd/demo -reconcile
```

> **The reconciler finds the orphan and asks CockroachDB Cloud's audit log what
> actually happened. It matches on a username derived from the idempotency key,
> so this is proof that this specific intent ran, not a guess about how the world
> looks.**

*Dashboard goes green.*

> **Committed. Memory now matches reality. The action was not repeated.**

*Now the control. Switch to the terminal.*

```sh
go test ./internal/control/ -run TestControl_DoubleActsOnCrash -v
```

> **Same incident, same API, same crash point, against the architecture everyone
> actually builds: a relational database plus a separate vector store.**

*Read the output line off the screen.*

> **Two operations. It scaled the cluster twice for one incident.**

*Click **Head to head** in the sidebar.*

> **And that's not a claim, it's a recorded measurement. Same experiment, both
> architectures, real process kills.**

## 1:50 — 2:15 · Refusing to guess

```sh
go run ./cmd/demo -escalate
go run ./cmd/demo -reconcile
```

> **This time the action is a delete. A delete leaves nothing behind, so an
> absent user is equally consistent with an operator having removed it.**
>
> **The verifier can't prove authorship, so it returns Unknown and stops.**

*Dashboard turns amber, "needs a human".*

> **Most frameworks have two answers: done, and not done. The third answer —
> "I don't know, a human should look" — is what stops an agent from either acting
> twice or writing a false history.**

*Type a reason into the box on screen, click **I confirmed it happened**.*

> **And it's recorded as an operator's judgement, never as machine verification.**

## Recovery, if something goes wrong mid-take

| Symptom | Fix |
|---|---|
| Dashboard cluttered | `go run ./cmd/demo -reset`, start the take again |
| An intent is stuck PENDING | That is an escalation. Resolve it on screen, or `anchorctl escalations` |
| ccloud says not logged in | `ccloud auth login` |
| "user already exists" | `go run ./cmd/demo -cleanup` |
